1. Why is building a port scanner from scratch more impressive than using Nmap?
Anyone can execute nmap -sV target from a terminal. Building this project from scratch proves you understand:
  • How operating system network sockets are initialized, configured, and bound.
  • How TCP 3-way handshakes work at the RFC 793 protocol level.
  • How non-blocking I/O and thread-pool concurrency manage hundreds of simultaneous network connections without CPU bottlenecking.
  • How to parse low-level OS error codes (WSAECONNREFUSED vs WSAETIMEDOUT) into meaningful security intelligence.
2. What is the packet-level difference between Open, Closed, and Filtered states?
  • OPEN: The target server responds to our SYN packet with a SYN-ACK packet. Our scanner completes the handshake with an ACK and transitions the socket to an established connection.
  • CLOSED: The target host is reachable, but no application is listening on that port. The target OS kernel automatically replies with an active RST (Reset) packet, triggering ECONNREFUSED.
  • FILTERED: A firewall (stateful inspection or cloud security group) intercepts and silently drops our SYN packet. No response returns, causing our socket to reach its timeout threshold (ETIMEDOUT).
3. How does Banner Grabbing work in this tool?
Once a TCP connection is established, services like SSH (22), FTP (21), and SMTP (25) proactively send unprompted identification strings (e.g., SSH-2.0-OpenSSH_8.9p1). For web and database services (80, 443, 6379), our scanner transmits tailored protocol probes (e.g. HEAD / HTTP/1.1 or INFO\r\n) to extract version headers and fingerprint the running software.
